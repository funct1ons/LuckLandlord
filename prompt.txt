你现在负责从零设计并实现一款完整、可玩的 PC 单机 Roguelike 构筑策略游戏。

游戏核心设计高度参考《Luck be a Landlord》这一类：

**老虎机 + 符号构筑 + 随机选择 + Combo + 阶段性债务/租金压力 + Roguelike 重开。**

但不要制作简单的老虎机模拟器。

真正的核心应该是：

> 玩家一开始几乎无法控制随机结果；
>
> 随着不断选择符号、删除垃圾符号、获得道具、构建组合，
>
> 玩家逐渐把“随机老虎机”变成一台按照自己策略运行的收益机器。

这是一款：

**随机性提供问题，构筑负责解决问题**

的策略游戏。

参考《Luck be a Landlord》的设计思想，但不得直接复制其：

- 游戏名称
- 美术
- UI
- 文本
- 具体符号名称
- 图标
- 音效
- 独有事件
- 独有道具
- 原版数值表

核心玩法机制可以借鉴，但所有具体内容应原创。

这是一款纯单机、虚拟货币游戏：

**不得包含真钱充值、提现、真实赌博、联网博彩等功能。**

---

# 一、最终目标

开发一个：

**小体量，但完成度很高，可以连续玩很多局的 PC 单机 Roguelike 游戏。**

最终游戏应该具有：

- 强烈的“一局再来一次”动力
- 大量符号协同
- 清晰的构筑路线
- 明显的成长曲线
- 爆炸式 Combo
- 有压力的阶段目标
- 很好的数字反馈
- 漂亮的 UI 和动画
- 足够好的平衡性
- 很低的运行环境要求

不要停留在：

> 点击 Spin → 随机金币 → 再点击 Spin

这种老虎机 Demo。

---

# 二、技术原则

最重要的工程原则：

> 轻依赖、轻环境、完全离线、容易维护。

使用：

- HTML5
- CSS3
- Vanilla JavaScript
- SVG
- Canvas（仅在真正适合动画/粒子效果时使用）
- Web Audio API
- localStorage
- 可选 PWA

原则上禁止：

- React
- Vue
- Angular
- Electron
- Unity
- Godot
- npm 运行依赖
- Node 后端
- 数据库
- 在线 API
- CDN
- 大型 UI 库
- 大型动画库

最终游戏应该：

```text
双击/打开网页即可玩
```

或者：

```powershell
python -m http.server 8000
```

即可运行。

Python 只能作为可选开发服务器，不能成为游戏运行依赖。

# 四、原创世界观

请自行设计游戏名称和世界观。

可以采用类似：

> 玩家欠下一笔巨额债务。
>
> 某天在廉价出租屋里得到一台奇怪的旧老虎机。
>
> 机器每运行一次都会生成不同的东西。
>
> 玩家发现，只要不断改装机器、加入新的符号并建立特殊组合，就可能产生越来越高的收益。

>
> 每一次付款期限都比上一次更加困难。

- 星际能源税

# 五、核心循环

整个游戏必须围绕：

```text
Spin
 ↓
老虎机结算
 ↓
获得金币
 ↓
从随机候选中选择一个新符号
 ↓
修改自己的符号池
 ↓
继续 Spin
 ↓
产生更复杂 Combo
 ↓
达到付款期限
 ↓
支付债务
 ↓
获得道具 / 特殊奖励
 ↓
进入下一阶段
 ↓
压力越来越大
```

最终：

```text
完成所有债务阶段
→
获得胜利
```

或者：

```text
无法付款
→
本局结束
```

# 六、老虎机盘面

推荐默认：

```text
5 × 4
```

共：

```text
20 个位置
```

每次 Spin：

从玩家当前拥有的 Symbol Pool 中抽取符号填充盘面。

重要：

老虎机视觉上可以像老虎机，

但内部机制实际上更接近：

```text
Deck Builder
```

玩家的 Symbol Pool 就相当于：

```text
牌组
```

如果玩家拥有：

```text
27 个符号
```

每次随机抽其中：

```text
20 个
```

显示。

因此：

增加一个垃圾符号，会降低优质符号出现概率。

删除垃圾符号本身就是强力操作。

建议：

```text
每个债务阶段约 5～10 次 Spin
```

例如：

```text
第一阶段
6 Spins
需要支付 40

第二阶段
7 Spins
需要支付 90

第三阶段
7 Spins
需要支付 180

第四阶段
8 Spins
需要支付 350

……
```

不要直接采用固定表。

需要通过模拟调整。

整局时间目标：

```text
20～40 分钟
```

熟练玩家：

```text
15～25 分钟
```

# 八、Spin 的爽感

Spin 是游戏最频繁的操作。

必须做好。

一次 Spin 应该：

```text
点击 SPIN
↓
滚轮/卡槽快速运动
↓
逐列停止
↓
基础收益出现
↓
Combo 开始触发
↓
符号高亮
↓
金币飞出
↓
倍率计算
↓
总收益不断跳涨
↓
最终数字定格
```

普通 Spin：

```text
约 1～2 秒
```

大型 Combo：

允许更长。

但必须提供：

```text
快速动画
跳过动画
```

选项。

高手不能被动画拖慢。

第一版正式内容建议：

```text

```

至少 60 个。


每个 Symbol 至少具有：

```javascript

    tags,

    icon,

    effects
```

例如：

# 十三、符号设计类别

必须存在多种不同机制。

至少覆盖以下类别。

## 1. 基础生产者

例如：

```text
每次出现 +1
每次出现 +2
```

用途：

前期稳定收入。

---

## 2. 邻接强化

例如：

```text
每邻近一个植物，+2
```

或者：

```text
使相邻机器类符号收益 ×2
```

---

## 3. 消耗型

例如：

```text
猫吃鱼
矿工开采矿石
厨师使用食材
盗贼偷走宝石
```

消耗另一个符号获得高收益。

---

## 4. 成长型

例如：

```text
种子
↓
幼苗
↓
植物
↓
结果
```

需要若干 Spin 才成长。

---

## 5. 转换型

例如：

```text
矿石
→
宝石
```

或者：

```text
牛奶
→
奶酪
```

---

## 6. Destroy 型

某些符号完成作用后：

```text
自我销毁
```

或：

```text
销毁其他符号
```

这可以帮助压缩牌池。

---

## 7. 永久成长型

例如：

```text
每吃掉一个水果
永久 +1
```

这是非常重要的 Build Around 机制。

---

## 8. 倍率型

例如：

```text
相邻符号收益 ×2
```

或者：

```text
本轮所有 Technology 标签 ×1.5
```

倍率不能太泛滥。

---

## 9. 复制型

例如：

```text
复制邻近符号效果
```

强度高。

应放在高稀有度。

---

## 10. Wildcard

可以：

```text
临时视为多个 Tag
```

产生复杂 Combo。

---

## 11. 风险型

例如：

```text
80% +5
20% -10
```

或者：

```text
连续存活越久收益越高
但有概率消失
```

---

## 12. 条件型

例如：

```text
如果现金 < 50
收益 ×3
```

或者：

```text
如果本轮没有重复 Symbol
额外 +15
```

---

## 13. Debuff / Junk

例如：

```text
垃圾
债务
诅咒
故障
```

占据 Symbol Pool。

玩家需要想办法删除或利用它们。

# 十六、避免“强制套装”

Build 不应该意味着：

```text
只收同一种标签即可。
```

好的构筑应该允许：

```text
Farm + Food
Machine + Gem
Animal + Magic
```

出现跨体系 Combo。

目标是产生：

> “等等，这两个东西居然能一起用！”

这种发现感。

# 十七、每次 Spin 后的选择

普通情况下，每次 Spin 后：

随机出现：

```text
3 个 Symbol
```

玩家可以：

```text
选择一个
```

或者：

```text
Skip
```

必须允许 Skip。

否则后期会被迫污染自己的 Symbol Pool。

# 十八、Reroll

玩家拥有有限：

```text
Reroll Token
```

可以重新生成候选。

例如：

```text
♻ ×2
```

Reroll 是重要资源。

不要无限免费刷新。

# 十九、Remove Token

存在：

```text
Remove Token
```

用于永久删除一个 Symbol。

这是极其重要的构筑资源。

因为：

```text
减少垃圾
=
提高核心 Combo 抽取概率
```

UI 中必须让玩家明确理解这一点。

# 二十、Items / Relics

除了 Symbol，还必须有独立：

```text
Item
```

系统。

建议：

```text
30～50 个 Item
```

Item 不进入老虎机。

而是在整局游戏中持续生效。

例如：

```text
所有 Animal +1

每第五次 Spin 获得 10

第一个被销毁的 Symbol 收益 ×3

Common Symbol 出现概率降低

拥有少于 20 个 Symbol 时，全局 +10%
```

注意：

Item 应该改变规则。

不要全部只是：

```text
+5%收益。
```

# 二十一、阶段奖励

每完成一次债务：

玩家从：

```text
3 个 Item
```

中选择一个。

某些阶段可以奖励：

```text
Reroll Token
Remove Token
特殊 Symbol
特殊 Item
```

因此债务阶段同时承担：

```text
压力节点
+
成长节点
```

两个作用。

---

# 二十二、债务系统

债务/房租是游戏的节奏控制器。

UI 中始终明显显示：

```text
距离付款：5 Spins

目标：120
当前现金：83
```

随着最后几次 Spin 临近：

视觉和音效增加少量压力。

例如：

```text
最后 3 Spin
```

开始明显提示。

但不要烦人。

---

# 二十三、付款规则

到期限时：

如果：

```text
cash >= payment
```

则：

```text
扣除 payment
→
进入下一阶段
```

否则：

```text
Run Over
```

玩家失败。

不要允许无限延期。

---

# 二十四、Risk / Reward

游戏中必须有一些真正需要判断的风险机制。

例如：

```text
高收益但会生成 Junk
```

```text
每次 +10，但 10% 概率永久消失
```

```text
收益翻倍，但下一次付款增加
```

```text
立即获得 50，但加入 3 个 Debt Symbol
```

这种：

```text
现在变强
vs
未来风险
```

应该大量存在。

---

# 二十五、特殊商店

可以加入轻量商店。

但不要让商店破坏核心构筑。

例如每个债务阶段后：

```text
黑市商店
```

随机出售：

```text
Remove Token
Reroll Token
特殊 Item
一次性升级
```

价格很贵。

玩家需要考虑：

```text
花钱变强
vs
留钱交债
```

# 二十六、事件系统

可以设计：

```text
20～30 个随机事件
```

但不要过度。

例如：

```text
下一阶段 Rare 概率提高
```

```text
债主提高本阶段付款金额，
但奖励额外 Item
```

```text
机器发生故障：
随机加入一个 Junk
```

```text
获得神秘包裹：
三选一特殊 Symbol
```

事件应增加变化。

不能让结果主要由事件决定。

# 二十七、Effect Engine

这是整个工程最重要的技术部分之一。

禁止把所有逻辑写成：

```javascript
if (...) {
   ...
}
else if (...) {
   ...
}
```

堆成巨大函数。

建立通用：

```text
Effect Resolver
```

模型。

每个 Spin：

```text
1. Roll Board
2. 建立 Board State
3. 初始化基础收益
4. 收集 Trigger
5. 加入 Effect Queue
6. 顺序解析 Effect
7. Effect 可以生成新的 Trigger
8. 继续解析
9. 直到 Queue 为空
10. Final Multiplier
11. 更新金币
12. 生成动画事件
```

---

# 二十八、Trigger Queue

必须有：

```text
Trigger Queue
```

明确处理触发顺序。

例如：

```text
ON_SPIN
ON_APPEAR
ON_ADJACENT
ON_CONSUME
ON_DESTROY
ON_TRANSFORM
ON_GAIN
ON_END_SPIN
```

必须明确：

```text
什么时候执行
谁先执行
谁后执行
```

否则后期 Combo 很容易出现 Bug。

---

# 二十九、防止无限循环

例如：

```text
A 触发 B
B 触发 C
C 又触发 A
```

必须有保护。

至少：

```text
MAX_TRIGGER_DEPTH
MAX_EFFECTS_PER_SPIN
```

如果发现异常：

开发环境报告。

正式环境不能卡死浏览器。

# 三十、结算顺序

为所有效果定义稳定规则。

例如：

```text
基础值
↓
固定加法
↓
邻接效果
↓
消耗/转换
↓
倍率
↓
全局 Modifier
↓
最终奖励
```

具体顺序由你设计。

但是：

**一旦确定必须统一。**

不能不同 Symbol 偷偷采用不同计算逻辑。

# 三十一、动画与逻辑解耦

重要：

游戏逻辑不能依赖动画完成才能算正确。

正确结构：

```text
Game Engine
↓
生成 Resolution Log
↓
UI 播放 Resolution Log
```

例如：

```javascript
[
  {type:"highlight", symbolId:"cat-2"},
  {type:"consume", source:"cat-2", target:"fish-1"},
  {type:"gain", amount:8},
  {type:"destroy", target:"fish-1"}
]
```

UI 只是重放。

这样才能：

```text
快速模式
跳过动画
自动测试
```


# 五十二、新手引导

第一次进入：

不要长篇教程。

采用：

```text
4～6 步 Overlay
```

第一步：

> 点击 SPIN。机器会从你拥有的符号中抽取 20 个。

第二步：

> 每个符号都会产生不同收益。

第三步：

> Spin 后可以选择一个新的符号加入机器。

第四步：

> 某些符号之间会产生特殊组合。

第五步：

> 在倒计时结束前准备足够的钱支付债务。

第六步：

> 不要什么都拿。一个更精简的机器往往更强。

然后让玩家自己发现系统。

# 六十二、Randomness 设计原则

随机性分成：

### Input Randomness

例如：

```text
三选一 Symbol
老虎机抽取
Item 候选
```

### Output Randomness

例如：

```text
50% 概率爆炸
```

尽量更多使用：

```text
Input Randomness
```

因为它给玩家问题，

但让玩家自己决策。

过多：

```text
结果随机
```

会让策略失去意义。

# 雾港回收工坊：视觉重构提案（已批准 A）

> **已归档：** 保留当时问题、提案和处理证据，不再作为现行待办。当前入口见 [文档导航](../README.md)；视觉实现以 [VISUAL_SPEC](../VISUAL_SPEC.md) 为准。

用户已批准 A 方向及本地绘画资产/SVG混合制作，现已实施。本文保留评审时的问题、参考与设计理由；现行实现和验收边界以 [VISUAL_SPEC](../VISUAL_SPEC.md) 为准，不替换 GAME_IDENTITY。规则、故事与既有声音保持不变。

## 1. 建议方向

**雾港夜班 · 手绘工业奇幻工作台。**

一个潮湿港区里的小型工坊：窗外是冷雾、码头和远处灯火，窗内有暖工作灯、旧铜机器、玻璃器皿、植物材料与账簿。机器经过使用和维修，但仍受到照料。玩家应该感到这里值得保住，同时感到账单带来的压力。

视觉目标为：环境有空间，物件有重量，材料有奇异性，操作有清晰反馈。

推荐采用有体积与克制笔触的2D插画。背景和机器具有轻微透视，中央5×4盘面保持正面可读。整体不需要转成3D游戏。

### 备选方向

| 方向 | 气质与优势 | 代价与适配判断 |
| --- | --- | --- |
| A. 雾港夜班手绘工作台（推荐） | 冷雾包围暖室内，旧器物与奇幻材料并置，生活感和经营压力平衡 | 需要真正的场景及物件插画，最适合当前故事与声音结构 |
| B. 明亮复古炼金工坊 | 奶油纸、蜂蜜色木料、明亮植物与玻璃，亲切易读 | 整体更轻松，港口潮湿与账单压力会减弱 |
| C. 深色精密工业终端 | 强机械结构、仪表与高对比数字，运行反馈有力度 | 接近现有仪表面板方向，需要额外处理生活感；大幅增加机械装饰仍可能单调 |

## 2. 改版前画面的具体问题

以下是提案评审时欢迎、待机主界面和候选截图的历史判断：

1. **视觉重量过于平均。** 标题、五个读数、机身、牌库和底部操作都拥有完整面板与描边，多个区域竞争注意力。
2. **环境缺少深度。** 欢迎页虽然画了机器和灯，但大多是均匀线宽与平涂几何形；远景、房间和近处工作台的层次不足。
3. **材质区别不足。** 铜、漆面、玻璃、纸都依赖相近的描边和渐变；单色图标更像界面符号，缺少器物体积。
4. **背景色占比过高。** 大片相近深青与重复斜纹，使空盘和长时间操作显得单调。装饰线条常被覆盖在面板之后，难以形成真实结构。
5. **卡面信息与插画比例失衡。** 候选有较大的纸色区域，但插画只有小型线稿；空白没有帮助突出物件，卡牌更像说明框。
6. **故事细节没有成为视觉主角。** 盐雾、铜绿、修补痕迹、玻璃凝露和异相材料都可以服务世界观，目前大多没有形成可辨认的质感。

增加齿轮、纹理和光晕并不能单独解决这些问题。先确定构图、光线与材质，再制作局部细节。

## 3. 与故事和声音的对应

故事以潮湿港口、负债工坊、材料加工和机器协作为基础；“保住工坊”需要一个让玩家产生依恋的空间。

现有音频实现以低频C/G持续音、低通噪声雾层、稀疏五声音阶铜击为背景，配合机械启动、短促停列与入账确认音。此判断来自音频代码与玩家对当前听感的认可，不宣称本轮已经真实设备试听。

| 声音结构 | 对应画面 |
| --- | --- |
| 低频与雾层 | 窗外有远近层次的雾港，机器有低亮、稳定的待机状态 |
| 稀疏铜击 | 局部暖铜高光、远港灯点、少量晶体或玻璃亮点 |
| 机械启动与停列 | 启动键压下、指示灯响应、插槽按既有节奏依次停稳 |
| 收益与付款确认 | 待入账数字定格、账簿记账、付款盖章，视觉反馈简短 |

环境动作慢，操作反馈快。避免所有齿轮、指针和灯同时循环运动，也不为装饰而伪造有游戏含义的读数。音乐与音效以保留为前提。

## 4. 色彩与材质

初拟色板需以首张样稿验证，不直接替换现行令牌：

| 职责 | 颜色示意 | 用法 |
| --- | --- | --- |
| 房间深部 | #142126 | 远离灯光的墙面与结构阴影 |
| 雾港环境光 | #718D92 | 远景港口、窗口冷光，降低细节对比 |
| 旧铜中间色 | #A66F48 | 机身局部连接件与受光边缘 |
| 工作灯暖光 | #E3BA79 | 主操作、物件受光面，控制覆盖面积 |
| 纸张与骨白 | #E5D8BA | 账单、卡牌规则区与主要文字 |
| 玻璃与植物 | #83AFA0 | 生产材料小范围辅色 |
| 异相点色 | #9A88BA | 指定异相物件，避免全局紫色光晕 |

材质区分来自结构与光线：铜有不连续高光和接缝氧化；珐琅面有大片低反差与少量磨损；玻璃有厚边、液面与折射提示；纸张只有轻微纤维和边缘变化；木台纹理沿同一方向。

统一主要光源、接触阴影、透视和细节密度。磨损只出现在受力边、接缝和常用部位。文字底面保持安静，不能把“精致”做成到处都有污渍和花边。

## 5. 欢迎首屏

构图以约三分之二空间呈现工坊关键画面，其余容纳标题与操作；实际比例随窗口调整。

- 主画面由前景工作台、中景回收机、远景雾港窗组成；机器工作区是暖光焦点。
- 标题形成独立字形与招牌关系。正文采用清晰字体，避免依赖描边、像素感或过度字距。
- 首层只保留一句身份／目标、主要操作、图鉴与设置；完整背景文字和模式详情分层展开。
- 有存档时突出“继续”，没有存档时突出“开始”；新局模式和覆盖确认保留。
- 教程选择保持可见；不让说明文字占据整个首屏。
- 只有雾、少量灯光或蒸汽进行轻微环境动画；减少动态时静止。

启动仍始终进入首屏，不自动恢复游戏。

## 6. 对局主界面

中央机器必须占据最主要视觉位置，同时保留盘面的可读几何结构。

```text
┌──────────────────────────────────────────────────────────────┐
│ 工坊招牌       现金 / 待入账            图鉴 · 帮助 · 菜单   │
│                                                              │
│ 本期账单夹       暖灯下的回收机                    构筑柜     │
│ 应付 / 缺口     ┌─────────────────────┐          生产牌库    │
│ 剩余运行        │  ○   ○   ○   ○   ○  │          本局升级    │
│                 │  ○   ○   ○   ○   ○  │          查阅与整理  │
│ 刷新券          │  ○   ○   ○   ○   ○  │                      │
│ 删除券          │  ○   ○   ○   ○   ○  │                      │
│                 └─────────────────────┘                      │
│                 运行键 · 本轮收入摘要                        │
│                    详细账本展开入口                          │
└──────────────────────────────────────────────────────────────┘
```

- 现金与待入账是一组清楚的数字，不做五个完全相同的大仪表。
- 本期应付、剩余运行与真实缺口集中在账单夹中；不能用“进度条”暗示已经支付。
- 右侧生产牌库和升级可用标签切换，保持常用入口明显；保留查看各实例与移除操作。
- 机身边缘承担结构，盘面外围可以轻微透视，二十个插槽保持正面；不表现为可拖拽摆牌。
- 空槽改用有凹陷和遮挡关系的结构，降低重复斜纹、格号与亮边的视觉干扰。
- “运行”做成与机器一体的实体启动键，文字依然清楚，鼠标与键盘语义不变。
- 主界面内必要控件按1366×768验证；侧边列表可以内部滚动，关键操作不依赖页面下滚。

布局是方向草图，最终尺寸以可读性和真实长文案样稿决定。

## 7. 生产牌、候选、详情与图鉴

采用统一物件设计，两档绘制：

- **盘面小图**：保留物件轮廓、主要材料色和一两处关键结构，在32–48px仍可辨认。
- **候选及详情大图**：约120–160px以上的插画区，增加光照、体积、材质与使用痕迹；不直接放大现有32px线稿。

例如：

- 凝雾软囊：半透明带凝露的软囊、纤维束口、浅色雾芯。
- 分温夹：不同材料的夹口、连接铆钉和受热痕迹，呈现可使用的工具。
- 微盐安瓿：厚玻璃边、液面、盐晶残留和小型纸标签。
- 先支邮戳：铜制印章、木柄、朱印与票据共同建立账务意味。
- 帮手牌：在物件图之外建立一致的胸像或剪影尺度，服装、工具服务既有职业身份，不新增角色系统。

候选卡采用“上部物件插画—名称与用途—完整效果—操作”的明确层级。外观可以像工坊物件档案或采购样张，但按钮仍明确表示加入生产牌库，不暗示新增商店或购买费用。

规则文字不能因美术调整而隐去条件、代价和例外。详情、图鉴与牌库复用同一物件形象、色板和排版体系。

## 8. 素材与技术方向

仅在HTML面板上加边框与渐变，难以达到目标。建议将美术资产与界面布局分别制作，并在首张样稿里一起检验。

现行 VISUAL_SPEC 限制“所有正式图形使用SVG、禁止位图”；建议批准后调整为：

- UI图标、路径、轮廓与可缩放装饰使用SVG。
- 场景与复杂物件允许本地WebP／PNG绘画资产。
- 文字与可交互区域使用HTML/CSS，不烘焙到背景图中。
- 所有资源随项目保存，运行时不联网；低端表现与减少动态有静态回退。

SVG也可以承载细致插画，但不能以文件格式代替绘画质量。素材无论如何制作，都要经过轮廓、光源、材质、风格与缩放检查；复杂生成图需要处理文字、重复结构和物件一致性。

本轮外部图片仅用于风格研究，没有放入游戏资源。参考作品的价值在构图、物件叙事与视觉层级，最终建立雾港自己的机器和材料形象。

## 10. 批准后的实施顺序

1. **先验证一套视觉样稿。** 欢迎首屏、填满20格的对局主界面、三张候选；样稿包含玻璃、植物、金属、票据、晶体等代表物件。用正常尺寸检验风格，而不只看局部放大图。
2. **再建立资产规范。** 固定光源、视角、轮廓、配色、描边与阴影强度，形成大小图标准；再扩展64生产牌与32升级，避免批量产出后返工。
3. **接入统一界面。** 完成主界面、候选、详情、图鉴、设置与结局，并清理旧样式覆盖关系。
4. **检查交互与性能。** 保留教程、焦点、快捷键、测试DOM、五列盘面、离线、独立UI存储及动画隔离。

完成标准：

- 第一眼能识别“雾港中的工坊”，机器有明确空间位置。
- 1366×768能看清盘面、账单与主要操作；更大桌面尺寸有留白，390px兜底无横向溢出。
- 满盘、长名称、长效果、临期提示、禁用状态与大数字不会破坏布局。
- 全部物件在正常游戏尺寸下可区分，复杂材质不影响规则文字。
- 没有不一致的光源、悬浮阴影、重复噪声、边缘锯齿或未统一的原生控件。
- 场景动作与现有声音反馈相配，减少动态模式仍完整可用。
- 规则、RNG、付款表、存档schema与故事设定保持不变。

**批准结论：采用 A 方向，允许本地绘画资产与SVG混合制作。** 当前资产是原创程序化2D插画；环境采用SVG源稿/本地PNG烘焙，96件物件采用重新绘制的128单位彩色SVG，不冒称真人手绘。
